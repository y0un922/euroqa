\begin{abstract}
本文讨论检索增强生成（Retrieval-Augmented Generation，RAG）系统的评估与迭代，对象是欧标（EN\,199x）中文问答系统。该系统已跑通端到端链路，并持久化答案、引用、检索上下文与分块得分、证据评估轨迹、工具调用、token 用量及时延。人工标注目前只有甲方约 30 道评估题（正确性、完整性、多余/编造、总体判定四列自由文本）。在此条件下，本文给出：结构化评测集的构造方式（参考答案等 gold 字段由闭源模型生成，属弱监督）；从 RAGAS、RAGChecker、DeepEval、TruLens、ARES 中选取的端到端与诊断指标及其形式化定义；以及按流水线环节划分的候选改动集合与 A/B 接受规则——定位到某一环节后，只在该环节的有限旋钮上做单变量试验。指标均标明计算口径、数据依赖与当前能否直接计算。
\end{abstract}

\section{引言}
% ============================================================

本文为已在运行的欧标中文 RAG 问答系统整理一套可重复的评估与迭代流程。在线路径大致为：问题进入后先做查询分解，再对每个子查询做向量与 BM25 双路检索，经 RRF 融合与交叉编码器重排，补充父块与证据评估，最后由生成端组织带引用的中文答案。过程数据已落盘。标注侧目前只有甲方约 30 道题的 Excel，四列为正确性、完整性、多余/编造与总体判定（A/B/C）。样本太少时，单独报一个准确率意义不大，更适合做版本间成对比较，并用置信区间约束结论。

正文侧重方法：写清系统保存了哪些结果、哪些参数确实可调，而不绑定某一版代码路径。指标沿用现有框架，不另起一套名字。改动则限制在真实旋钮上——如 \texttt{vector\_top\_k}、\texttt{bm25\_top\_k}、\texttt{rerank\_top\_n} 与重排模型、分解与补检索相关逻辑、生成 prompt 与引用后处理等。流程上按``看哪项指标变差 $\rightarrow$ 落到哪一环 $\rightarrow$ 在该环候选里改一项 $\rightarrow$ 再判定是否接受''推进。

本文不讨论：需要重训生成器的方案（如 Self-RAG 的 reflection token\cite{selfrag}）；依赖开放网搜的纠错（如 CRAG\cite{crag}，与固定规范库冲突）；依赖外部独立知识源的核验（如 FActScore\cite{factscore}）；需要数百条人工标注训练 judge 的校准（如 ARES 的 PPI\cite{ares}）；以及改前端、重采用户反馈一类工作。

\section{数据集构建}
% ============================================================

\subsection{唯一标注资产}

甲方 Excel 是目前唯一的人工标注输入，约 30 道题。每条记录包含四列自由文本评分：

\begin{itemize}[leftmargin=2.5em]
  \item \textbf{正确性}：答案在事实上是否正确（允许部分正确）。
  \item \textbf{完整性}：答案是否覆盖该题的要点。
  \item \textbf{多余/编造}：是否存在无据可查或凭空生成的内容。
  \item \textbf{总体判定}：A（可直接用）、B（需修改）、C（不能用，需重写）。
\end{itemize}

上述字段均为自由文本而非结构化标签，因此首先需要进行归一化。

\subsection{人工标签归一化}

归一化将自由文本映射为有序类别。表~\ref{tab:normalize} 给出映射方案。做法是先由闭源模型根据自由文本内容建议映射，再逐条人工复核——自由文本中包含``公式表达不完整''''首段存在消极声明''等难以机械归类的信号，复核不可省略。归一化结果按题号对齐，每条记录包含四个维度的类别标签及归一化可信度（高/低两档）。可信度低的题仅进入开发集，不进入保留集。

\subsection{参考字段生成（弱监督）}

归一化仅解决质量标签；多数指标还需要参考答案（reference answer）、可核验说法（gold claims）、支持证据（gold evidence）与负样本（negative chunks）。这些字段由闭源模型生成，本质为弱监督。生成流程如下：

\begin{enumerate}[leftmargin=2.5em]
  \item 以某一模型家族（如 GPT 系）为生成端：以原始问题为输入生成参考答案，再将参考答案拆分为可独立核验的原子说法（atomic claims）。该``长文本 $\rightarrow$ 原子事实''思路与 FActScore\cite{factscore} 及 RAGChecker\cite{ragchecker} 的 claim 级评估一致。
  \item 对每条说法，从语料库中定位支持它的分块作为 gold evidence。定位方式不限——可由模型阅读分块后判断支持关系，也可由人工辅助检索——但标准是``该分块在语料中确实存在且确实支持该说法''，而非``当前检索器能够召回''。若当前检索配置召不到某条 gold evidence，不丢弃该证据，而标注为检索缺口（retrieval gap）保留——此正是召回类指标应暴露的问题。
  \item 从语料中选取话题相近但不支持对应说法的分块作为负样本，用于噪声侵入率等诊断指标。
  \item 换用另一模型家族（如 Claude 系）对上一步结果做反向核验：验证每条 gold evidence 是否确实支持对应说法，参考答案是否存在事实错误或遗漏。两家不一致处标注后交人工复核。
\end{enumerate}

\textbf{独立性约束}：用于生成参考答案与 gold evidence 的模型家族，必须与后续评估所用 LLM-as-judge 的模型家族不同，以避免``同一模型族既造金标又打分''的循环验证风险。

质量校验关注三点：(i) gold evidence 必须能在语料中定位到（而非仅被模型``认为存在''）；(ii) 拆出的说法应与人工评分中的完整性判断高度吻合；(iii) 记录两模型家族的同意率，作为参考质量的元指标。

\subsection{数据划分}

归一化后的约 30 道题拆为三套互不重叠的题目集：

\begin{itemize}[leftmargin=2.5em]
  \item \textbf{开发集}（dev，约 15 道，50\%）：日常迭代的主评估集。每轮单变量改动后在 dev 上评估并做 A/B 判定；允许反复使用。
  \item \textbf{测试集}（test，约 9 道，30\%）：阶段性 checkpoint。每 $k$ 轮（建议 $k\in\{3,4,5\}$）调用一次，用于检测对 dev 的过拟合。
  \item \textbf{保留集}（holdout，约 6 道，20\%）：仅在里程碑版本合并时使用一次。核心纪律是``只看不调''——一旦根据 holdout 结果回头改参，即构成数据泄露。
\end{itemize}

划分采用分层抽样：按题目类别（概念题、参数查找、宽泛题等）与总体质量（pass / minor-revise / major-revise / reject）交叉分组，再按约 $5{:}3{:}2$ 比例从各组抽样，以保证各集合分布大致均衡。

dev 仅约 15 道题，单次点估计波动较大。因此除报告均值外，一律附带配对 bootstrap 置信区间，并固定参与比较的题集合（judge 分歧剔除后的有效样本需写入当轮日志）。留一交叉验证在此样本量下与全样本均值几乎等价，\textbf{不}作为稳健性保证，仅可作可选敏感性检查。划分方案一经确定即写入版本号并与代码版本绑定；日常迭代期间不修改划分，holdout 不参与日常调参。

\subsection{这套数据能做什么、不能做什么}

能做：两个版本比高低、找短板、看有没有回退、相对 gold 估完整性。不能做：给出有统计意义的绝对准确率、外推到未见规范、代替结构专业人员签字。根子仍是题少、gold 弱监督、以及语料与考题同源。

\section{评估指标}
% ============================================================

\subsection{指标筛选原则}

指标不求多。入选条件是：(i) 已有成熟框架、计算口径清楚；(ii) 数据系统已保存或评测集能补齐；(iii) 三十题量级下仍能做成对比较或给区间。每项写清定义、出处、数据依赖、能否直接算、以及门槛类型。

可算性分三类：
\begin{itemize}[leftmargin=2.5em]
  \item \textbf{立即可算}：所需数据已在流水线中保存，部署 judge 即可执行。
  \item \textbf{搭完数据集可算}：依赖 gold claims 或 gold evidence。
  \item \textbf{需小改动可算}：需新增少量埋点或改写少量代码（如重排序退化标志）。
\end{itemize}

门槛类型分三类：硬门槛（一旦显著退化即拒绝该版本）、软门槛（不可超出预设上界）、趋势参考（只看方向，不设硬阈值）。

\subsection{统一符号}
\label{sec:notation}

全文采用如下统一符号。对单条评测样本，记：
\begin{itemize}[leftmargin=2.5em]
  \item $q$：用户查询；$a$：系统生成答案；$a^{\star}$：参考答案（弱监督）。
  \item $C=\{c_1,\ldots,c_m\}$：进入生成阶段的检索上下文，按重排序后顺序排列；$m$ 由截断量与 token 预算共同决定。
  \item $\mathcal{S}(a)=\{s_1,\ldots,s_{|\mathcal{S}(a)|}\}$：由答案 $a$ 拆出的原子说法集合。
  \item $\mathcal{G}=\{g_1,\ldots,g_{|\mathcal{G}|}\}$：由 $a^{\star}$ 拆出的 gold claims。
  \item $E^{+}\subseteq \mathcal{U}$：支持 $\mathcal{G}$ 的 gold evidence 分块集合；$\mathcal{U}$ 为语料库全体分块。
  \item $E^{-}\subseteq \mathcal{U}$：负样本分块（话题相近但不支持对应说法）。
  \item $\mathrm{supp}(s,C)\in\{0,1\}$：说法 $s$ 是否被 $C$ 中至少一个分块所支持（由 LLM-as-judge 或 NLI 判定）。
  \item $\mathrm{Cite}(a)$：答案中出现的引用标记所指向的源分块集合。
  \item $y\in\{\text{pass},\text{minor-revise},\text{major-revise},\text{reject}\}$：人工总体质量标签；$\hat{y}$ 为 judge 给出的同口径判定。
\end{itemize}
对含 $n$ 道题的评测集，指标默认先逐题计算，再对题取平均；需要排名感知时在题内先聚合。

\subsection{端到端指标（LLM-as-judge）}

端到端指标由 LLM 裁判对最终答案打分，回答``答案本身好不好''。裁判模型家族必须与生成端不同，以减轻自评偏置\cite{zheng2023judge,wataoka2024selfpref}。每道题由两个家族分别打分；不一致的题标注存疑、从硬门槛分母中剔除，并在报告中写明剔除数量与剔除前分母。为避免小样本下的选择性净化，设定：(1) 剔除后有效样本数不得低于 15，否则该轮整体仅作趋势参考；(2) 若剔除率超过 $30\%$，该轮整体仅作趋势参考，并检查 judge prompt 或拆分规范是否需要调整。

\subsubsection{忠实度（Faithfulness）}

将答案拆为原子说法，逐条判断是否被检索上下文支持，取支持率\cite{ragas,trulens}：
\begin{equation}
  \mathrm{Faith}(a,C)
  \;=\;
  \frac{1}{|\mathcal{S}(a)|}
  \sum_{s\in\mathcal{S}(a)}
  \mathrm{supp}(s,C)\,,
  \qquad
  |\mathcal{S}(a)|>0\,.
  \label{eq:faith}
\end{equation}
数据需求：答案 $a$ 与上下文 $C$（立即可算）。门槛：硬门槛。

\subsubsection{幻觉率与非幻觉率}

幻觉率定义为不被任何检索分块支持的说法比例\cite{ragchecker}：
\begin{equation}
  \mathrm{Hall}(a,C)
  \;=\;
  1-\mathrm{Faith}(a,C)\,.
  \label{eq:hall}
\end{equation}
为统一``越高越好''方向，版本接受规则中使用非幻觉率 $\mathrm{NonHall}(a,C)=\mathrm{Faith}(a,C)$。数据需求同忠实度；门槛：硬门槛。

\subsubsection{答案完整性（Claim Recall）}

以 gold claims 被答案覆盖的比例衡量完整性\cite{ragchecker}：
\begin{equation}
  \mathrm{Comp}(a,\mathcal{G})
  \;=\;
  \frac{1}{|\mathcal{G}|}
  \sum_{g\in\mathcal{G}}
  \mathrm{covered}(g,a)\,,
  \label{eq:comp}
\end{equation}
其中 $\mathrm{covered}(g,a)\in\{0,1\}$ 表示 gold claim $g$ 是否被答案 $a$ 语义覆盖（由 judge 判定）。数据需求：答案 $+$ gold claims（搭完数据集可算）。门槛：趋势参考。

\subsubsection{答案正确性（Rubric Correctness）}

采用 G-Eval 风格的有序量表\cite{geval,deepeval}。记 $\mathrm{rubric}(a,a^{\star})\in\{1,2,3,4,5\}$ 为相对参考答案的事实一致性评分，则
\begin{equation}
  \mathrm{Corr}(a,a^{\star})
  \;=\;
  \frac{\mathrm{rubric}(a,a^{\star})-1}{4}
  \;\in\;[0,1]\,.
  \label{eq:corr}
\end{equation}
归一化到 $[0,1]$ 是为了与其余指标在回归检查中共用同一量纲。数据需求：答案 $+$ 参考答案（搭完数据集可算）。门槛：趋势参考。

\subsubsection{引用精确率（Citation Precision）}

对答案中的每个引用标记，判断其是否指向真实存在且内容与被引用说法匹配的源分块\cite{ragchecker}：
\begin{equation}
  \mathrm{CitP}(a,C)
  \;=\;
  \frac{1}{|\mathrm{Cite}(a)|}
  \sum_{r\in\mathrm{Cite}(a)}
  \mathrm{valid}(r;a,C)\,,
  \qquad
  |\mathrm{Cite}(a)|>0\,.
  \label{eq:citp}
\end{equation}
$\mathrm{valid}(r;a,C)=1$ 当且仅当引用 $r$ 既在有效源范围内，又在内容级与对应说法一致。若答案无任何引用且系统要求强制引用，则该题 $\mathrm{CitP}=0$。注意：仅检查引用编号是否在合法范围内的``引用有效性''是格式检查，与此处内容级 $\mathrm{CitP}$ 不同。数据需求：答案 $+$ 源分块 $+$ 上下文（立即可算，需 judge prompt）。门槛：硬门槛。

\subsubsection{总体判定匹配}

\begin{equation}
  \mathrm{Match}
  \;=\;
  \frac{1}{n}
  \sum_{i=1}^{n}
  \mathbf{1}\!\left[\hat{y}_i = y_i\right]\,.
  \label{eq:match}
\end{equation}
数据需求：答案 $+$ 人工总体质量（立即可算）。门槛：趋势参考。

\subsection{诊断指标（确定性或半确定性计算）}

诊断指标主要从过程数据计算，回答``问题出在哪一层''。

\subsubsection{上下文召回率（gold-evidence chunk recall）}

\begin{equation}
  \mathrm{CRec}(C,E^{+})
  \;=\;
  \frac{|E^{+}\cap C|}{|E^{+}|}\,,
  \qquad
  |E^{+}|>0\,.
  \label{eq:crec}
\end{equation}
此处采用 \textbf{分块级} gold-evidence 覆盖率：衡量 $E^{+}$ 中有多少证据块落入 $C$。它与 RAGAS 的 claim 级 context recall\cite{ragas} 相关但不完全等价——若一条 claim 有多块等价证据，未召回冗余块也会拉低本指标。构造 $E^{+}$ 时应尽量为每条 claim 指定最小充分证据集，以减轻冗余惩罚。数据需求：$C,E^{+}$（搭完数据集可算）。门槛：趋势参考。

\subsubsection{上下文精确率（排名感知）}

采用 ranking-aware 形式\cite{ragas}。记 $r_i=\mathbf{1}[c_i\in E^{+}]$（或与 $E^{+}$ 高度相关的软判定），前 $k$ 位精确率为
$\mathrm{P@}k=\frac{1}{k}\sum_{i=1}^{k}r_i$，则
\begin{equation}
  \mathrm{CPrec}(C,E^{+})
  \;=\;
  \frac{
    \sum_{k=1}^{m} \mathrm{P@}k\cdot r_k
  }{
    \max\!\left(1,\ \sum_{k=1}^{m} r_k\right)
  }\,.
  \label{eq:cprec}
\end{equation}
数据需求：$C,E^{+}$（搭完数据集可算）。门槛：趋势参考。

\subsubsection{噪声侵入率}

\begin{equation}
  \mathrm{Noise}(C,E^{-})
  \;=\;
  \frac{|E^{-}\cap C|}{|C|}\,,
  \qquad
  |C|>0\,.
  \label{eq:noise}
\end{equation}
对应 RAGChecker 的 noise sensitivity 思想\cite{ragchecker}。数据需求：$C,E^{-}$（搭完数据集可算）。门槛：趋势参考。

\subsubsection{证据覆盖率}

记 $C_{\mathrm{ev}}\subseteq C$ 为实际进入证据评估阶段的分块集合（可从工具调用轨迹还原），则
\begin{equation}
  \mathrm{ECov}(C_{\mathrm{ev}},E^{+})
  \;=\;
  \frac{|E^{+}\cap C_{\mathrm{ev}}|}{|E^{+}|}\,.
  \label{eq:ecov}
\end{equation}
用于区分``检索未召回''与``召回后在截断/准入中被丢弃''。数据需求：$C_{\mathrm{ev}}$（工具轨迹）与 $E^{+}$（gold evidence），故\textbf{搭完数据集可算}，而非仅凭轨迹即可算。门槛：趋势参考。

\subsubsection{重排序退化率}

\begin{equation}
  \mathrm{RDeg}
  \;=\;
  \frac{1}{n}
  \sum_{i=1}^{n}
  \mathbf{1}\!\left[\mathrm{rerank\_failed}_i=1\right]\,.
  \label{eq:rdeg}
\end{equation}
其中 $\mathrm{rerank\_failed}_i$ 表示第 $i$ 题重排序服务失败并触发全零得分兜底。数据需求：需新增退化标志（需小改动可算）。门槛：软门槛。

\subsubsection{自评校准度}

系统置信度信号 $u_i\in\{\text{高},\text{中},\text{低}\}$ 与 judge 忠实度 $\mathrm{Faith}_i$ 之间的有序一致率，采用 Kendall 等级相关：
\begin{equation}
  \tau
  \;=\;
  \frac{
    N_c - N_d
  }{
    \sqrt{(N_0-T_u)(N_0-T_f)}
  }\,,
  \label{eq:tau}
\end{equation}
其中 $N_0=\binom{n}{2}$，$N_c$/$N_d$ 为一致/不一致对数目，$T_u$、$T_f$ 分别为 $u$ 与 $\mathrm{Faith}$ 上的 ties 修正项。由于 $u$ 仅三档且 $n$ 较小，ties 较多，$\tau$ 仅作粗略趋势，不宜赋予稳定校准解释。数据需求：系统置信度 $+$ $\mathrm{Faith}$（立即可算）。门槛：趋势参考。

\subsubsection{运维类指标}

端到端时延的 P50/P95、每题 token 总用量、agent 步数（证据评估与补充检索轮次）直接由日志统计，本文不另给形式化定义；均作为软门槛或趋势参考使用。

此外，\textbf{重排序分数分布}以 gold evidence 在重排序得分中的排名中位数及 P25/P75 描述，属描述性诊断，不设单一标量公式。

\subsection{为什么不纳入更多指标}

RAGAS 的 answer relevancy 度量答案是否直接回应问题\cite{ragas}。在许多 RAG 场景中，忠实度低的答案往往也答非所问，二者可能相关；但在欧标问答中亦可能出现``忠实但不切题''或``切题但依据不足''，故在样本量增大前暂不纳入。RAGAS 的 entity recall 依赖命名实体边界，对中文欧标文本（公式编号、条款号、材料参数）边界定义不明确，暂不纳入。ARES 的 PPI 校准需要数百量级人工标注\cite{ares}，本项目仅约 30 题，不满足条件。TruLens 的 context relevance 在计算上接近上下文精确率的简化版\cite{trulens}，保留后者即可。DeepEval 与 RAGChecker 的 hallucination 口径重叠，取 RAGChecker 版本\cite{ragchecker,deepeval}。Self-RAG、CRAG、FActScore 等因训练成本或外部知识源依赖而剔除，但其局部思想（原子事实核验、低置信时重试）已吸收到 gold 构造与瓶颈映射中\cite{selfrag,crag,factscore}。

\subsection{LLM-as-judge 的偏置控制}

LLM 裁判常见问题包括位置偏置\cite{zheng2023judge}、自评偏置\cite{wataoka2024selfpref}，以及偏爱冗长、偏爱``看起来权威''的表述等\cite{ye2024justice}。实践上采用三道约束：裁判与生成不同模型族（只能减弱自评偏置，不能指望消掉）；成对比较时交换顺序各判一次并取保守结果；每题两家打分，一致才进硬门槛。即便如此仍可能有残余偏差，因此 judge 指标一律带 bootstrap 区间，里程碑版本再抽人工复核。

\section{迭代方法论}

\subsection{系统现状与可调范围}
\label{sec:levers}

下面先按实现写清在线链路和旋钮，再谈``指标差时动哪一环''。描述以当前 \texttt{server} 配置与编排为准（\texttt{ServerConfig}、\texttt{HybridRetriever}、agent 预取与生成），不把实验目录或未接线字段算成日常可调项。

\subsubsection{在线链路（实现形态）}

一次问答大致经过：
\begin{enumerate}[leftmargin=2.5em]
  \item \textbf{查询分解}：\texttt{decompose\_query} 产出改写问句、子查询列表、是否闲聊/是否需要检索、结构化过滤条件等。主路径上分解是常开的，不是环境变量开关。
  \item \textbf{混合检索}：对每个子查询并发做稠密检索（Milvus）与 BM25（Elasticsearch）；原始中文问句另作一路向量补召回（不对中文再做 BM25，以免污染英文索引）。多路结果用 RRF 融合（实现中 $k_{\mathrm{RRF}}=60$）\cite{rag,bm25,dpr}，再按来源做跨文档截断。
  \item \textbf{重排序}：交叉编码器（默认 \texttt{BAAI/bge-reranker-v2-m3}）对融合后的候选打分并截断到 \texttt{rerank\_top\_n}\cite{monobert,nogueira2019}。失败时回退为未重排的前 $n$ 条，目前缺少显式退化标志（对应后文 $\mathrm{RDeg}$ 需小改动）。
  \item \textbf{上下文扩展}：按 \texttt{parent\_chunk\_id} 取父块并入证据包；可选交叉引用闭包由 \ctt{retrieval\_auto\_cross\_ref\_closure} 控制（默认关）。
  \item \textbf{证据评估与补检索}：对证据覆盖做评估；零命中时可放大 \texttt{top\_k} 重试，评估指出缺口时再补检索，补充轮次有上限（实现中最多 2 轮）。生成 agent 还可调用 \texttt{search}/\texttt{lookup\_object} 做纠正性补证，最大轮次为代码常量（当前为 4）。
  \item \textbf{生成}：在预检索证据与大纲约束下写中文答案，引用须落在已出现的 \texttt{[Ref-$N$]} 上；引用编号另有后处理对齐。系统对外置信度由重排分映射：最高分 $\ge 0.85$ 为高、$\ge 0.5$ 为中，否则为低（规则映射，不是模型直接输出的概率）。
\end{enumerate}

\textbf{未实现或不走主路径的项}：HyDE\cite{hyde}；纯向量/纯 BM25 的在线切换（主路径固定双路）；ColBERT 类晚交互重排\cite{colbert}。配置里虽有 \texttt{query\_expansion\_llm\_*}、\texttt{max\_context\_tokens} 等字段，但前者主要用于离线/实验检索脚本，后者在当前 agent 主路径中几乎不起截断作用——日常迭代不以它们为优先旋钮。

\subsubsection{旋钮分级}

按改动成本分成三档。

\textbf{配置级}（改环境变量 / \texttt{ServerConfig} 即可，默认值见括号）：
\begin{itemize}[leftmargin=2.5em]
  \item 召回：\texttt{vector\_top\_k}（30）、\texttt{bm25\_top\_k}（30）；
  \item 重排：\texttt{rerank\_top\_n}（10）、\texttt{rerank\_model}/\texttt{rerank\_provider}；
  \item 超时：重排请求、agent、整请求三类 deadline（配置项 \texttt{*\_timeout\_seconds}）；
  \item 可选：交叉引用闭包（默认关）、\texttt{agentic\_search\_enabled}（默认关，实验向）。
\end{itemize}
agent 预取会把单次检索的有效 \texttt{top\_k} 压到实现常量（如初始 8），故``改全局 \texttt{vector\_top\_k}''与``预取实际候选数''未必一一对应，调参时对照日志中的 \texttt{top\_k}。

\textbf{prompt / 代码级}（改模板或少量常量，需发版）：
\begin{itemize}[leftmargin=2.5em]
  \item 分解与评估：\texttt{decompose} 的 prompt 与输出约束；证据评估与大纲生成逻辑；
  \item 生成：QA agent 系统指令（引用纪律、证据不足时的表述、补工具条件等）；
  \item 常量：补充检索轮次上限、agent \texttt{max\_turns}、groundedness 分界（0.85 / 0.5）、RRF 的 $k$、跨文档每源上限等。
\end{itemize}

\textbf{专项工程}（成本高，不进日常单变量循环）：
\begin{itemize}[leftmargin=2.5em]
  \item 更换 \texttt{embedding\_model} 并重建向量索引；
  \item 调整切块策略 / 重叠并重建 Milvus 与 ES；
  \item 引入 HyDE、更换检索范式、接入 ColBERT 类重排等未实现路线。
\end{itemize}

上述取舍与已有 RAG 调参研究\cite{wang2024best,ammar2025hyper} 一致：召回量与重排截断影响面大且便宜；chunk size 与嵌入模型影响面大但重建贵。

\subsection{版本接受规则}

判定时把方向统一：硬门槛一律``越高越好''，软门槛一律``越低越好''。因 $\mathrm{NonHall}=\mathrm{Faith}$（式\eqref{eq:hall}），硬门槛集合里只留一项，避免重复计数：
\begin{align}
  G &= \{\mathrm{Faith},\ \mathrm{CitP}\}\,, \\
  S &= \{\mathrm{LatencyP95},\ \mathrm{TokenCost},\ \mathrm{RDeg}\}\,.
\end{align}
报告中可并行列出 $\mathrm{Hall}=1-\mathrm{Faith}$ 便于阅读，但不单独进入 $G$。本轮主优化指标为 $M$（例如 $\mathrm{Comp}$）。回归集 $R$ 为全部``越高越好''的端到端与诊断指标（不含 $M$ 自身及已在 $S$ 中的指标）。对方向为``越低越好''且不在 $S$ 中的指标（如 agent 步数），进入回归检查前先取负号，统一为``越高越好''。

给定基线版本 $v$ 与候选版本 $v'$，接受 $v'$ 需同时满足：
\begin{enumerate}[leftmargin=2.5em, label=(\arabic*)]
  \item 硬门槛不退化：$\forall g\in G,\ g(v')\ge g(v)-\epsilon_g$；
  \item 软门槛不破线：$\forall s\in S,\ s(v')\le s_{\max}$；
  \item 主指标有改善：$M(v')\ge M(v)+\delta$；
  \item 无显著回归：$\forall r\in R\setminus\{M\},\ r(v')\ge r(v)-\epsilon_r$。
\end{enumerate}

\subsection{阈值的统计校准}

$\epsilon_g$、$\epsilon_r$ 与 $\delta$ 的默认值均设为 $0.05$（在 $[0,1]$ 量表上），但实际使用时在开发集上做配对 bootstrap 校准：对 $v$ 与 $v'$ 在同一批 $n$ 道题上的逐题指标值配对，做 $B=1000$ 次有放回重采样，计算每次重采样的差值均值，取 $2.5\%$ 与 $97.5\%$ 分位数作为差值的 $95\%$ 置信区间。若某指标 bootstrap 区间宽度超过 $0.1$，则该指标本轮仅作趋势参考，不进入硬门槛。若硬门槛指标被降级为趋势参考的比例超过半数，本轮整体仅作趋势参考。时延与成本的软门槛上界取 $s_{\max}=1.2\times$ 基线对应值。

\subsection{迭代主循环}

算法~\ref{alg:loop} 给出迭代主循环。每次仅改一个变量；评估在门禁集 $G_{\mathrm{set}}=D_{\mathrm{dev}}\cup F$ 上进行（$F$ 为历史失败样本）；测试集每 $k$ 轮做 checkpoint；holdout 仅在里程碑流程单独调用。

\begin{algorithm}[!t]
\caption{IterativeImprovementLoop}\label{alg:loop}
\begin{algorithmic}[1]
\State $v\gets$ 基线；$F\gets$\Call{LoadFailures}{}; $G_{set}\gets D_{dev}\cup F$
\State $\mathrm{tried}[L]\gets\emptyset\ \forall L$；$\text{iter}\gets 0$
\While{预算未耗尽}
    \State $R_v\gets$\Call{RunEval}{$v,G_{set}$}；$L^{\star}\gets$\Call{LocateBottleneck}{$R_v$}
    \If{$L^{\star}$ 为人工项 \textbf{or}（硬门槛达标 \textbf{and} $M$ 无改善空间）} \State \textbf{break} \EndIf
    \State $a\gets$\Call{PickSingleVarAction}{$L^{\star},\mathrm{tried}[L^{\star}]$}
    \If{$a=\bot$} \State 切换下一环节或 \textbf{break} \EndIf
    \State $v'\gets$\Call{ApplyAction}{$v,a$}; $R_{v'}\gets$\Call{RunEval}{$v',G_{set}$}
    \State $\text{dec}\gets$\Call{ABDecide}{$R_v,R_{v'}$} \Comment{accept/reject/inconclusive}
    \State $\mathrm{tried}[L^{\star}]\gets\mathrm{tried}[L^{\star}]\cup\{a\}$；$\text{iter}\gets\text{iter}+1$
    \If{$\text{dec}=\text{accept}$}
        \State 快照 $(v_{\mathrm{prev}},F_{\mathrm{prev}})$；令 $v_{\mathrm{cand}}\gets v'$，$F_{\mathrm{cand}}\gets F\cup$\Call{NewFailures}{$R_{v'}$}
        \If{$\text{iter}\bmod k=0$ \textbf{and} \Call{CheckpointGate}{$v_{\mathrm{cand}},D_{test}$}$=0$}
            \State 恢复 $(v,F)\gets(v_{\mathrm{prev}},F_{\mathrm{prev}})$；$G_{set}\gets D_{dev}\cup F$；\textbf{continue}
        \EndIf
        \State 提交 $v\gets v_{\mathrm{cand}}$，$F\gets F_{\mathrm{cand}}$；\Call{SaveFailures}{$F$}
        \State $G_{set}\gets D_{dev}\cup F$；清空 $\mathrm{tried}$
    \ElsIf{$\text{dec}=\text{inconclusive}$}
        \State 仅记趋势，不更新 $v$
    \Else
        \State 记录拒绝原因
    \EndIf
\EndWhile
\State \Return $\{v\}$ \Comment{预算耗尽且硬门槛未达标时附诊断报告}
\end{algorithmic}
\end{algorithm}

\subsection{A/B 判定伪代码}

算法~\ref{alg:ab} 给出 A/B 判定的流程骨架。$\epsilon_g$、$\epsilon_r$、$\delta$ 与 $s_{\max}$ 由 bootstrap 校准确定；$G$、$S$、$M$、$R$ 为预定义集合。\textsc{LocateBottleneck} 返回优先环节 $L^{\star}$，\textsc{PickSingleVarAction} 再查表~\ref{tab:stage-algos} 得到 $a\in\mathcal{A}_{L^{\star}}$。辅助函数约定见第~\ref{sec:helpers} 节。

\begin{algorithm}[!t]
\caption{ABDecide（门禁集；配对 bootstrap 三态）}\label{alg:ab}
\begin{algorithmic}[1]
\Require 基线/候选在同一批题上的逐题指标（用于配对 bootstrap）
\Ensure $\text{dec}\in\{\text{accept},\text{reject},\text{inconclusive}\}$，以及 reason
\State 对每个相关指标 $m$，由配对 bootstrap 得差值区间 $[d_L^{(m)},d_U^{(m)}]$
\State $\text{hard\_fail}\gets 0$；$\text{hard\_inc}\gets 0$；$\text{reason}\gets[\,]$
\For{$g \in G$} \Comment{硬门槛：不可显著退化}
    \If{$d_U^{(g)} < -\epsilon_g$} $\text{hard\_fail}\gets 1$；$\text{reason}.\text{append}(g)$
    \ElsIf{区间跨越 $-\epsilon_g$} $\text{hard\_inc}\gets\text{hard\_inc}+1$
    \EndIf
\EndFor
\If{$\text{hard\_fail}=1$} \State \Return $\text{reject}$ \EndIf
\For{$s \in S$}
    \If{$s(R_{v'}) > s_{\max}$} \State \Return $\text{reject}$ \EndIf
\EndFor
\If{$d_U^{(M)} < \delta$} \State \Return $\text{reject}$ \Comment{主指标无改善} \EndIf
\For{$r \in R\setminus\{M\}$}
    \If{$d_U^{(r)} < -\epsilon_r$} \State \Return $\text{reject}$ \EndIf
\EndFor
\If{$\text{hard\_inc}>|G|/2$ \textbf{or} $M$ 的区间跨越 $\delta$}
    \State \Return $\text{inconclusive}$ \Comment{仅趋势参考，不更新基线}
\EndIf
\If{$d_L^{(M)}\ge\delta$ \textbf{and} 全部硬门槛 $d_L^{(g)}\ge -\epsilon_g$}
    \State \Return $\text{accept}$
\EndIf
\State \Return $\text{inconclusive}$
\end{algorithmic}
\end{algorithm}

\subsection{配对 Bootstrap 判定}

当样本量仅 $15$--$20$ 道题时，点估计不可靠。对 $v$ 与 $v'$ 的逐题指标配对 $(x_i,y_i)_{i=1}^n$，做 $B=1000$ 次有放回重采样，得到差值均值序列 $\{\bar{d}_b\}_{b=1}^{B}$ 及其 $95\%$ 区间 $[d_L,d_U]$。判定规则：

\begin{itemize}[leftmargin=2.5em]
  \item 硬门槛 $g\in G$：若 $d_L\ge -\epsilon_g$ 则通过；若 $d_U<-\epsilon_g$ 则拒绝；若区间跨越 $-\epsilon_g$，该指标本轮仅作趋势参考。
  \item 主指标 $M$：若 $d_L\ge\delta$ 则通过；若 $d_U<\delta$ 则拒绝；跨越则仅作趋势参考。
  \item 回归集 $R$：若 $d_U<-\epsilon_r$ 则拒绝；若 $d_L\ge -\epsilon_r$ 则通过；跨越则仅作趋势参考。
\end{itemize}

若硬门槛中被降级为趋势参考的比例超过半数，本轮整体仅作趋势参考，不更新基线。算法~\ref{alg:ab} 中的阈值比较是上述区间判定在伪代码层的简化表达。

\subsection{辅助函数约定}
\label{sec:helpers}

\begin{itemize}[leftmargin=2.5em]
  \item \textsc{RunEval}$(v,D)$：在集合 $D$ 上跑完整链路，按式\eqref{eq:faith}--\eqref{eq:tau} 与表~\ref{tab:e2e}、\ref{tab:diag} 计算指标，返回指标字典。
  \item \textsc{LocateBottleneck}$(R)$：按表~\ref{tab:bottleneck-stage} 将最劣未达标指标映射为 $L^{\star}$ 或``人工/运维项''；硬门槛优先。
  \item \textsc{PickSingleVarAction}$(L^{\star},\mathrm{tried})$：从 $\mathcal{A}_{L^{\star}}\setminus\mathrm{tried}$ 中选动作；仅允许标签为配置或 prompt/代码；优先配置；若为空返回 $\bot$。
  \item \textsc{ApplyAction}$(v,a)$：在 $v$ 的配置副本上执行 $a$，生成 $v'$；$v$ 保持不变。
  \item \textsc{NewFailures}$(R)$：返回硬门槛未达标或总体判定为 reject 的题号。
  \item \textsc{LoadFailures}$()$ / \textsc{SaveFailures}$(F)$：失败样本集的持久化读写；首次为空集。
  \item \textsc{CheckpointGate}$(v,D_{test})$：在 test 上配对 bootstrap；任一硬门槛显著退化则返回 0，否则返回 1。
  \item \textsc{HoldoutGate}$(v,D_{hold})$：逻辑同 CheckpointGate，仅里程碑合并时调用。
\end{itemize}

\subsection{回归与失败回流}

每接受一个版本，将该轮硬门槛未过或总体质量为 reject 的题目追加到失败样本集 $F$ 并持久化。$F$ 作为门禁集一部分参与后续评估，防止已修复题回退。$F$ 跨迭代累积、不重置。若 $F$ 持续膨胀而硬门槛未见改善，应退回上一稳定版本并更换调参杠杆（换环节或换 $\mathcal{A}_L$ 内另一候选）。

\subsection{采纳与剔除理由}

\textbf{采纳}：RAGAS 的 faithfulness 为 ref-free（仅需 $a$ 与 $C$）\cite{ragas}，适合当前标注稀缺设定；其 context precision/recall 在本文中作为诊断指标，\textbf{计算依赖} $E^{+}$（搭完数据集可算），口径沿用 RAGAS。RAGChecker 的 claim/citation 级精确率—召回率与幻觉定义构成式\eqref{eq:faith}--\eqref{eq:citp} 的方法基础\cite{ragchecker}。DeepEval / G-Eval 的点量表用于 $\mathrm{Corr}$\cite{geval,deepeval}。TruLens 的三要素框架用于组织``答案—问题—上下文''关系\cite{trulens}。ARES 的区间思想在小样本下以配对 bootstrap 实现\cite{ares}。

\textbf{剔除}：ARES 需数百量级标注训练轻量 judge\cite{ares}，本项目约 30 题不足。Self-RAG 需强化学习重训生成器\cite{selfrag}，本项目生成端为闭源模型。CRAG 的开放网搜回退与固定 Eurocode 语料冲突\cite{crag}，但``低置信则细化查询或重试''保留在瓶颈映射中。FActScore 依赖外部知识源\cite{factscore}，本项目语料即知识边界；其原子事实拆分已并入 gold claims 构造。

\subsection{调参与检索组件参考}

调参侧主要参照 Wang 等对切块、嵌入、检索与重排的系统实验\cite{wang2024best}，以及 Ammar 等对 chunk size、召回量、重排截断的影响面分析\cite{ammar2025hyper}。组件层面则对应 DPR\cite{dpr}、BM25\cite{bm25}、RAG\cite{rag}、交叉编码器重排\cite{monobert,nogueira2019}；ColBERT\cite{colbert} 与 HyDE\cite{hyde} 仅作对照。结合本系统实现：日常优先动 $k_{\mathrm{vec}}$、$k_{\mathrm{bm25}}$、$k_{\mathrm{rr}}$ 与重排模型；切块与嵌入更换算专项；HyDE 与纯单路检索未接主路径。

% ============================================================
\section{落地约束}
% ============================================================

\textbf{数据}：大约 30 题只适合成对比较和看趋势，不宜报单独准确率。gold 是弱监督，人工标签归一化也有边界模糊，结果宜用区间表述。

\textbf{指标}：$\mathrm{CRec}$、$\mathrm{CPrec}$、$\mathrm{ECov}$ 依赖 $E^{+}$，要等评测集建完；$\mathrm{RDeg}$ 要在重排失败回退处加标志。对外置信度来自重排分规则（$\ge 0.85$/$\ge 0.5$），不是生成模型概率，$\tau$ 校准的是这条映射。

\textbf{迭代}：默认一次改一个旋钮。若怀疑 $k$ 与截断强交互，先在 dev 做两因子小网格再决定是否放开。切块、换嵌入、HyDE 等不进日常循环；在线检索保持混合，不做纯向量/纯 BM25 切换。

\textbf{上线}：评估只给出相对表现和区间，不能代替``能不能上线''的业务决定；后者仍须规范领域人员把关。
